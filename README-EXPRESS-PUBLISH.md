# Публикация экспресс-заявок для перевозчиков

## Что изменено
- В админ-панели экспресс-заявок появилась кнопка «Опубликовать для перевозчиков».
- При публикации сервер в транзакции создаёт запись в `cargos`, связывает её с исходной записью `express_requests` и помечает заявку как `in_progress`.
- Повторная публикация одной экспресс-заявки блокируется.
- Витрина перевозчика использует `LEFT JOIN` вместо `JOIN users`, поэтому грузы без зарегистрированного клиента также отображаются.
- Для экспресс-грузов в карточке перевозчика показываются имя и телефон заказчика, так как у него нет личного кабинета.
- Убрана отдельная верхняя форма входа в админ-панель: используется существующая авторизация через кабинет.

## Установка
1. Сделайте резервную копию проекта и PostgreSQL.
2. Распакуйте архив и скопируйте содержимое `Cargogo/cargogo` в корневую папку проекта (где находится `server.js`).
3. Сохраните свой `.env`; файл `.env` в архив не включён.
4. В терминале проекта выполните `npm install`, затем `npm start`.
5. Откройте админ-панель, перейдите в «Экспресс-заявки» и нажмите «Опубликовать для перевозчиков» у нужной заявки.
6. Войдите под аккаунтом перевозчика и откройте список доступных грузов.

## Примечание
При старте приложения `ensureSchema()` добавляет новые поля `cargos.express_request_id` и `express_requests.published_cargo_id`. Ручное изменение базы не требуется.

Публикация создаёт активный одобренный груз. Поскольку у экспресс-клиента нет аккаунта, существующий сценарий выбора отклика и чата через кабинет клиента к нему автоматически не применяется. Перевозчик видит телефон и может связаться с заказчиком напрямую. Полный интерфейс управления откликами администратором можно добавить отдельно.

Проверены синтаксис `server.js`, `public/admin.js` и `public/cabinet.js` через `node --check`. Подключение к реальной PostgreSQL и полный браузерный сценарий в этой среде не запускались.
