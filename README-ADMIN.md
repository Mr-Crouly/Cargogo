# CARGOGO — административная панель

## Возможности
- Отдельная панель `/admin.html` с доступом только для адресов из `ADMIN_EMAILS`.
- Очередь модерации новых грузов и рейсов: принять, отклонить с обязательной причиной, скрыть.
- Общая статистика, список пользователей, полный список грузов и рейсов.
- Блокировка/разблокировка пользовательских аккаунтов.
- Журнал действий администратора.
- Новые объявления получают статус модерации `pending`; до одобрения они не показываются в публичной витрине и каталогах.
- Существовавшие до обновления объявления мигрируют как `approved`, чтобы не исчезнуть из каталога.

## Настройка администратора
1. Откройте `.env` на сервере.
2. Добавьте адрес аккаунта, который должен быть администратором:

   ```env
   ADMIN_EMAILS=admin@ваш-домен.md
   ```

   Несколько адресов указываются через запятую.
3. Перезапустите сервер.
4. Зарегистрируйте обычный аккаунт CARGOGO с этим email (роль клиента/перевозчика не важна).
5. Откройте `http://localhost:3000/admin.html` и войдите с этим email и паролем.

Административная привилегия не выдаётся через форму регистрации. Сервер проверяет email по переменной окружения и актуальную запись пользователя в БД при каждом административном запросе. Не добавляйте в `ADMIN_EMAILS` адреса обычных пользователей.

## Миграция базы
При запуске сервер автоматически добавляет поля `moderation_status`, `moderation_reason`, `moderated_at`, `moderated_by` для `cargos` и `trips`, поле `is_blocked` для `users` и таблицу `admin_audit`. Старые объявления получают `approved`; новые записи получают `pending`.

Резервная копия PostgreSQL перед обновлением всё равно рекомендуется:

```bash
pg_dump -U ИМЯ_ПОЛЬЗОВАТЕЛЯ -d ИМЯ_БАЗЫ > cargogo-backup.sql
```

## Важное поведение
- Отклонённое/скрытое объявление остаётся в БД и доступно администратору; оно не удаляется.
- Блокировка пользователя запрещает новые входы и последующие запросы по уже выданному JWT.
- Удаление пользователей из панели намеренно не предусмотрено, чтобы случайно не потерять историю заказов и переписок.
