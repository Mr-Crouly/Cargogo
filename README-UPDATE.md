# CARGOGO — обновление интерфейса и безопасности

## Что изменено
- Обновлена главная страница: адаптивный первый экран, блок поиска маршрута, карточки преимуществ, витрина грузов/рейсов и секция «Как это работает».
- Добавлено переключение RU / RO на главной странице и в окнах входа/регистрации. Выбор языка сохраняется в браузере.
- Названия городов в списках отображаются на румынском языке, но их исходные значения остаются прежними для совместимости с базой данных. Исправлено накопление пустых групп при смене языка.
- Добавлены базовые HTTP security headers, ограничение размера JSON-запроса и строгая CORS-политика (по умолчанию межсайтовые браузерные запросы не получают CORS-разрешения).
- Сервер теперь не запускается с отсутствующим или коротким JWT_SECRET.
- Добавлен переключатель светлой/тёмной темы на главной странице; настройка общая с личным кабинетом. - Гостевые карточки скрываются после подтверждённой авторизации и возвращаются после выхода. - Улучшена мобильная раскладка шапки, поиска, карточек и модальных окон.
- Архив не содержит `.env`, `.git` и `node_modules`.

## Установка
1. Распакуйте архив.
2. В папке `cargogo` создайте `.env` на основе `.env.example`.
3. Перенесите в `.env` параметры подключения к вашей PostgreSQL базе из старого локального `.env`.
4. Обязательно создайте новый JWT_SECRET. В терминале Node.js выполните:

   `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"`

   Скопируйте результат в `.env` как `JWT_SECRET=...`. Не публикуйте это значение.
5. Установите зависимости: `npm install`.
6. Запустите сервер: `npm start`.

## CORS
Если фронтенд и API открываются с одного адреса, оставьте `CORS_ORIGIN` пустым. Если фронтенд размещён на отдельном домене, укажите его полный origin, например `CORS_ORIGIN=https://example.md`. Несколько origin разделяются запятыми.

## Важно
В этом обновлении румынская локализация добавлена на главную страницу и в модальные окна авторизации/регистрации. Интерфейс личного кабинета пока остаётся на русском — его локализацию следует выполнить отдельным этапом, чтобы не затронуть сложную логику кабинета.

Существующий способ хранения JWT в localStorage сохранён для совместимости с текущими скриптами. Для следующего этапа безопасности рекомендуется перейти на HttpOnly cookies с CSRF-защитой.
